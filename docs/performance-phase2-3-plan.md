### 1. LRU 缓存实现（优先级：高）

**实施时间**: 2-3 小时  
**预期收益**: 10-15% 性能提升

**目标场景**:

- 重复查询相同的行数据
- 频繁访问的列统计信息
- 计算密集型的格式化结果

**实施计划**:

1. 创建通用 LRU 缓存类
   - 支持配置最大容量
   - 支持 TTL（生存时间）
   - 提供清理 API

2. 应用到 Parquet 数据访问
   - 缓存已加载的页面数据
   - 缓存列统计计算结果
   - 缓存格式化的单元格值

3. 添加缓存指标
   - 命中率监控
   - 内存使用监控
   - 性能基准测试

**示例代码结构**:

```typescript
class LRUCache<K, V> {
  constructor(capacity: number, ttl?: number);
  get(key: K): V | undefined;
  set(key: K, value: V): void;
  clear(): void;
  size(): number;
  hitRate(): number;
}

// 应用示例
const pageCache = new LRUCache<number, ParquetPage>(100);
const cellFormatCache = new LRUCache<string, string>(1000, 60000); // 1分钟TTL
```

**测试策略**:

- 单元测试：缓存行为（容量、TTL、LRU 淘汰）
- 集成测试：缓存在实际场景中的效果
- 性能测试：缓存前后的性能对比

### 2. Web Worker 集成（优先级：高）

**实施时间**: 4-6 小时  
**预期收益**: 15-20% 性能提升（大数据集）

**目标场景**:

- Parquet 文件解析（CPU 密集）
- 大数据集过滤和搜索
- 列统计计算

**实施计划**:

1. 创建 Worker 通信层
   - 消息类型定义
   - 请求/响应模式
   - 错误处理

2. 迁移 CPU 密集型任务
   - Parquet 解析移到 Worker
   - 搜索操作移到 Worker
   - 统计计算移到 Worker

3. 实现进度反馈
   - 长时间任务的进度条
   - 可取消的操作
   - 友好的错误提示

**架构设计**:

```
Main Thread              Worker Thread
    |                        |
    |----(parse request)---->|
    |                        | [解析 Parquet]
    |<---(progress 30%)------|
    |                        |
    |<---(progress 60%)------|
    |                        |
    |<---(result)------------|
    |                        |
```

**注意事项**:

- Worker 不能访问 DOM
- 数据传递使用 Transferable Objects（避免拷贝）
- 需要 fallback 机制（旧浏览器）

**测试策略**:

- 单元测试：Worker 通信协议
- 集成测试：端到端的任务执行
- 性能测试：Worker vs 主线程性能对比

### 3. 增量渲染（优先级：中）

**实施时间**: 3-4 小时  
**预期收益**: 10-15% 性能提升（10k+ 行）

**目标场景**:

- 初始加载大表格
- 搜索结果高亮
- 列统计显示

**实施计划**:

1. 实现分批渲染
   - 先渲染可见部分
   - 后台分批加载剩余数据
   - 使用 requestIdleCallback

2. 优化虚拟滚动
   - 动态调整渲染窗口
   - 预加载相邻页面
   - 优化滚动性能

3. 添加加载指示器
   - 骨架屏
   - 进度条
   - 平滑过渡

**实施示例**:

```typescript
function useIncrementalRender<T>(items: T[], batchSize: number = 50, delay: number = 16) {
  const [rendered, setRendered] = useState<T[]>([]);

  useEffect(() => {
    let index = 0;
    const renderBatch = () => {
      const next = items.slice(index, index + batchSize);
      setRendered((prev) => [...prev, ...next]);
      index += batchSize;

      if (index < items.length) {
        requestIdleCallback(renderBatch, { timeout: delay });
      }
    };

    renderBatch();
  }, [items]);

  return rendered;
}
```

**测试策略**:

- 性能测试：不同数据量的渲染时间
- 用户体验测试：感知加载速度
- 回归测试：确保功能完整性

### 4. 内存管理优化（优先级：中）

**实施时间**: 1-2 小时  
**预期收益**: 5-10% 性能提升

**目标**:

- 及时清理不用的数据
- 优化数据结构
- 防止内存泄漏

**实施计划**:

1. 审查事件监听器
   - 确保所有监听器有清理
   - 使用 AbortController
   - 避免闭包陷阱

2. 优化数据结构
   - 使用 WeakMap/WeakSet
   - 及时释放大对象
   - 使用对象池模式

3. 内存监控
   - 添加内存使用监控
   - 设置内存阈值警告
   - 提供手动清理 API

**重点检查项**:

- ✅ useEffect 清理函数
- ✅ 事件监听器注销
- ✅ Timer 清理
- ✅ 大对象释放
- ✅ 循环引用检查

**测试策略**:

- 内存泄漏测试：长时间运行检测
- 性能测试：内存使用趋势
- 压力测试：极限场景下的表现
