# ADR-0023 交互与无障碍：先让人听见，再让人看见

- 状态：已接受（2026-11-13，方向；实现待做）
- 日期：2026-11-13

## 背景

视觉那一轮（ADR-0022）把层次与动效钉住了，收口时留下三个具体缺口，都是从代码里量出来的，
不是主观感受：

- **parquet 只有值面板有 live region**。翻页、搜索命中、选中行列都是「看得见但听不到」：
  键盘 + 读屏用户翻一页之后不知道自己在哪一页，搜索完不知道有没有命中。这不是"体验差一点"，
  而是这条路径**没有出口**。
- **excel 还有 11 处字面时长**，不尊重 `prefers-reduced-motion`。parquet 已经 0、jsonl/json
  已经 0，只剩它——而"减少动效"是用户设置，不是按 view 分批的功能。
- 列宽 resizer **已经有**键盘路径（箭头 ±8、Shift ±32），所以"键盘可达"这条并不缺；缺的是
  **听得见的结果**。

上一轮还留下一个已知 papercut：打开字段面板的前 100 ms 内按 `i`，看到的是「Scan this column」
而不是 top-N（不影响正确性，再点一下就好）。

## 决定

1. **第一刀是可听反馈**。给 parquet 加一个 `aria-live="polite"` 的状态区，播报**结果而不是过程**：
   翻页后的行区间（`22–42 of 300`）、搜索的命中数、选中单元格的位置。输入过程中不播报，只在
   落定后播报一次——否则每敲一个键就有一条语音，那是噪声不是反馈。
2. **动效令牌扩到 excel 的 11 处**，并接上同一个 `prefers-reduced-motion` 归零规则。理由不是
   "顺手"，而是无障碍承诺必须全仓成立；按 view 分批等于承认有一半界面对某些用户不可用。
3. **键盘验收用 Tab 序列遍历**：从页面顶部开始，`Tab` 走完命令栏 → 侧栏 → 表头 → 单元格 →
   底栏，断言焦点不丢、不跳进死循环、每个可交互元素都能到达。配合 DOM 断言，不引入读屏环境
   （CI 里不稳定）也不引入 axe-core（规则噪声与品牌无关）。
4. **不做**：`i` 早开的 papercut **评估后放弃**（2026-11-13）。它的自然修法——在 ref 里记住那次点击、
   等 profile 应答到达时补触发扫描——被 React compiler 的三条规则拒绝（不可变 ref、`startScan` 的
   memoization 无法保持），而为 100 ms 窗口重写面板状态机、或加本仓第一条 lint 抑制，都不划算。
   影响是"多点一次"，记录在此，让下一次尝试从原因出发而不是重新发现一遍；
   不重排交互布局；不改键位。

## Considered Options

- **先修 `i` 早开的 papercut**：改动小、体验突兀，但它只影响前 100 ms 的一次点击，而 live region
  影响的是整条读屏路径。否决，排在后面。
- **在每一处状态变化上都挂 live region**：会得到"每敲一键播报一次"的噪声。否决，改为单一状态区
  - 落定后播报。
- **引入 axe-core**：能一次扫出大量规则，但它的告警与这个产品的品牌/布局强绑定，误报会训练人
  忽略它。否决；用针对性 DOM 断言。
- **CI 里跑真实读屏**：最接近真实，但 Linux CI 上装 NVDA/VoiceOver 不现实。否决，留作发布前人工检查。

## 后果

- `Parquet.tsx` 增加一个 derfer 过的播报文本（页区间 / 命中数 / 选中位置），复用现有的
  `sr-only` 样式；i18n 需要新键的地方尽量复用分页器与搜索已有的键，避免两套说法。
- `excel` 的 11 处字面时长换成 `--motion-*` 令牌；`prefers-reduced-motion` 下归零。
- 新增 UI 场景：`parquet-announce-pagination`（翻页后 live region 文本变化）、
  `parquet-announce-search`（命中数播报、空结果也播报）、`parquet-tab-order`（从顶到底走一遍）。
- `DESIGN.md` 增加一节「Audible feedback」，写清播报什么、什么时候播、以及"不播报输入过程"。
- 不做：读屏自动化、axe-core、键位调整、布局重排。
