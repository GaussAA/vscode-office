# ADR-0022 视觉与动效：在仪器语言内加层次，动效只做状态反馈

- 状态：已接受（2026-11-13，方向；实现待做）
- 日期：2026-11-13

## 背景

方向是「主攻视觉观感：界面、动画、流畅度、交互增强」。这句话在别的项目里等于一张自由票，
在这个项目里不是：`DESIGN.md` 已经是一套有硬规则的**仪器语言**——主题是唯一色源、不用
`box-shadow` 表达层级、区域之间不加分割线、颜色只做信号、数字一律 `tabular-nums`、浅色主题
对比度 ≥ 4.5:1 由闸门断言。最省事的「变好看」（阴影、卡片、渐入、视差）恰好逐条违反它。

同时有两个现实约束：

- **动效已有 34 处，但只有 2 处尊重 `prefers-reduced-motion`**。动效不是「加」，是「加得能被
  关掉」。
- **「流畅」目前没有量**。`verify:perf` 量的是字节数与解码耗时，它看不见滚动/翻页/选中期间
  掉了多少帧。没有量，视觉优化就只能靠主观判断，而主观判断在每次回归时都不作数。

## 决定

1. **主战场是 parquet 表格**。它是每天用的面，已有 71 条 UI 场景与性能闸门看守，改动能被断言、
   能被截图对比。另外两个 viewer 与全局外壳这一轮不动；只有共享组件（停靠面板、值面板）顺带受益。
2. **视觉语言不变，但在语言内加层次**。允许：用 `color-mix` 的底色混合区分**三段表面**
   （canvas 画布 / surface 表头与侧栏 / raised 停靠面板）、更大的内距、更明确的字阶
   （10px 大写标签 → 12–13px 正文 → 14px 区域标题）。仍然禁止：`box-shadow`、区域间 1px 分割线、
   主题外的颜色、第四种圆角（只用 8 / 6 / 4 / 3）。**`DESIGN.md` 是唯一事实来源，改语言必须先改
   文档再改样式**，否则下一个人会以为样式是例外。
3. **动效只做 120–180 ms 的状态反馈**：面板进出、行/列选中、hover/press、列跳转的平滑滞动。
   **不做**入场动画、不做骨架屏、不做滚动联动或视差。全部动效必须在
   `prefers-reduced-motion: reduce` 下**归零**（时长 0、直接到终态），这一条进闸门。
4. **「流畅」被定义成可测量的帧预算**：交互（滚动、翻页、选中、跳列）期间的**长任务**
   （> 50 ms）与**长帧**，用 `PerformanceObserver`（`longtask` / `long-animation-frame`）在无头
   浏览器里采集，与现有 `verify:perf` 并列。**先量现状，再定阈值；阈值只允许收紧**——反过来的
   顺序会得到一个永远绿的闸门。
5. **验收沿用 DOM 断言，新增三类**：动效时长落在窗口内、`reduced-motion` 下时长归零、交互不引起
   重排（行数/列宽不变）与无长任务。**不引入像素基线**：antd 与字体渲染的噪声会让 diff 变成
   「习惯性重基」，而重基一次就等于这条闸门再也不说话。

## Considered Options

- **像素基线回归**：确实能拦住「看起来变丑了」，但视觉回归的误报来自字体抗锯齿与 antd 内部布局，
  维护成本会转嫁到每次无关改动上。否决，除非将来出现只有像素能抓住的缺陷。
- **骨架屏与内容淡入**：parquet 首屏本地 200–600 ms，骨架屏大概率只闪一下——闪一下比没有更糟。
  否决，除非测量显示首屏 > 800 ms。
- **滚动联动（粘性表头阴影、滚动进度）**：与「不用阴影表达层级」直接冲突，且在虚拟表格上与
  `rc-virtual-list` 的 transform 滚动配合容易掉帧。否决。
- **重做设计 token（一次大重构）**：会把视觉改动和结构改动混在一起，回退一个就要回退全部。
  否决，改为逐面推进。
- **只打磨细节、语言完全不动**：风险最低，但「观感提升」会退化成「加几个 hover」，不解决问题。

## 后果

- `DESIGN.md` 先增加一节「表面层级（surface levels）」，写清三段底色的合成公式与各自用途；样式与
  截图跟随。三份 README 里的截图在改动稳定后重拍一次（`verify:ui --docs`）。
- 新增测量脚本（`scripts/perf/motion.mjs` 或并入现有 runner）：采集交互期间的长任务与长帧，
  先输出基线数字，再据此设阈值。
- 动效常量集中到一个模块（如 `src/react/util/motion.ts`）：时长、缓动、是否允许（读
  `prefers-reduced-motion`）。散落的 34 处 `transition` 逐面收敛，不一次性重写。
- 不做：像素基线、骨架屏、滚动联动、另两个 viewer、设计 token 大重构。
- 交互增强（键盘可达性、列宽拖拽等）**不在这一批**：它需要自己的一轮取舍，先做视觉与动效的地基。
